# VBA×Pythonプロジェクトを作成する

## 利用に必要な環境

VS Code標準タスクとWindows PowerShellを使用します。専用拡張やインストーラーは不要です。「Workspace Project Git」を使用している場合は、VS Codeの拡張機能一覧から「無効にする（ワークスペース）」を選び、必要に応じて再読み込みしてください。このワークスペースでは標準タスクのみを使用します。他のワークスペースでも使用している場合、アンインストールは不要です。

作成対象は、VBAとPythonの両ソース保存先を持つプロジェクト1種類です。種類選択はありません。

## VS Codeで実行する

1. `Workspace.code-workspace` またはワークスペース直下のフォルダーをVS Codeで開きます。
2. メニューの「ターミナル」→「タスクの実行」を選びます。
3. `New: VBA×Pythonプロジェクト新規作成` を選びます。
4. プロジェクト名を入力します。例: `Sample` を入力すると `Project Sample` が作成されます。`Project ` は自動で付くため入力しません。
5. インストール済みのPythonバージョンを入力します。既定は `3.13`、対応は `3.10` 以上です。指定したシステムPythonを使用します。
6. ターミナルの完了案内を確認します。Gitの初期化とステージングまで行い、Gitビューへの表示は標準Git拡張機能の自動検出に任せます。自動表示やフォーカス移動を保証するものではありません。
7. 通常はワークスペースを開いたまま、`Python: Select Interpreter` で指定したシステムPythonを選択します。子フォルダーの `.vscode/settings.json` は親ワークスペースには適用されません。その設定をそのまま使う場合だけ、プロジェクトを別ウィンドウで開いてください。

共通ツールはワークスペース直下の `.tools`、共通タスクと入力欄は `.vscode/tasks.json` にまとめています。`.vscode/settings.json` にはリポジトリ自動検出と検索深度（2階層）を設定しています。ワークスペースフォルダーを開く場合も、同じフォルダーを参照する `Workspace.code-workspace` を開く場合もこの設定を使います。

UserForm情報のCSV出力・反映タスクも共通タスクに登録しています。スクリプトとセットアップ要件は [`UserFormCsvExporter/README.md`](UserFormCsvExporter/README.md) を参照してください。実行タスクはExcelを起動し、反映タスクはブックを保存します。許可確認なしにAIが実行してはいけません。

作成に必要なソフトはGit for Windows、VS Code、Python Launcher（`py`）、Python 3.10以上です。使用できるPythonバージョンは `py -0p` で確認できます。VBAの実行にはExcelデスクトップ版を使用しますが、作成処理ではExcelを起動しません。実行ポリシーのBypassは、作成タスクが起動するPowerShellプロセスだけに適用します。

## Gitビューに表示されない場合

編集内容を保存し、`Developer: Reload Window` を実行すると、標準Git拡張機能が `Projects/Project 名前` など2階層以内のリポジトリを再検出します。それでも表示されない場合は `Git: リポジトリを開く` で、完了案内に表示された作成先を指定してください。ワークスペースへのフォルダー追加や、Gitの再初期化は不要です。Git拡張機能の有効化とワークスペースの信頼が前提で、除外設定や明示的に閉じたリポジトリの状態によっては再読み込みだけでは表示されません。

日本語案内は `New-Project.messages.json` をUTF-8指定で読み込みます。スクリプトを配布する場合は同じフォルダーに同梱してください。読み込みはプロジェクト作成前に行います。タスクは案内を表示するだけで、自動再読み込みはしません。

## 作成する内容

`Projects/_Template_Combined` をコピーし、`Projects/Project 入力した名前` を作成します。

- `Pysource` にPythonコード、`VBsource` にVBAソースを配置し、README・`requirements.txt`・Git管理をプロジェクト直下で共用します。
- 指定したシステムPythonの実行ファイルを `.vscode/settings.json` に設定します。仮想環境の作成、pip更新、パッケージ導入は行いません。依存関係は必要に応じて手動で導入します。
- 本番採用前の試作・検証を管理する `Sandbox` も含めます。利用手順はテンプレートの `Sandbox/README.md` を参照してください。
- テンプレートの隠しファイルもコピーします。`.git`、`.venv`、`venv`、`__pycache__` はコピーしません。
- コピー先で `git init -b main` を実行し、独立したリポジトリを作成します。テンプレートの履歴やリモートは引き継ぎません。
- `.gitignore` に仮想環境などの除外設定を補います。テンプレートの既存設定は保持します。
- `.vscode/settings.json` が既にある場合は上書きしません。

初回コミット、GitHubリポジトリの作成、`origin` の登録、pushは自動実行しません。完了時に表示されるコマンドを使い、登録対象を確認してからコミットしてください。PythonやVBAのコード、Excelブック自体の新規作成は行いません。

**ブックの注意:** ブック（`*.xlsm`、`*.xlsb`、`*.xlam`）は既定でGit対象外です。VBAソースとUserFormの `.frx` は管理対象にできます。Excel VBA Syncのエクスポート先は、そのプロジェクトの `VBsource` を選びます。ソース編集だけではブックは更新されません。

## PowerShellから直接実行する

Workspace直下で実行します。標準タスクと同じ作成処理を実行します。Gitビューへの明示的な登録は行わず、標準Git拡張機能の自動検出に任せます。

```powershell
& .\.tools\New-Project.ps1 -ProjectName "Sample" -PythonVersion 3.13
```

既存の作成先がある場合は、処理開始前にエラーで停止し、上書きしません。フォルダー名には空白や日本語も使えますが、パスやWindowsで使用できない文字は指定できません。

途中で失敗した場合は、調査できるよう作成途中のフォルダーを残します。エラーを解消し、そのフォルダーに必要なファイルがないことを確認したうえで削除するか、別の名前でタスクを再実行してください。テンプレートや他のプロジェクトは変更しません。

## 作成機能を検証する

```powershell
& .\.tools\Test-New-Project.ps1 -PythonVersion 3.13
```

作成タスクが1件であること、入力欄、名前の引用設定を検査します。一時フォルダーでVBA×Python構成の生成、Sandbox、システムPythonの実行、Git設定、上書き防止、種類指定による単独作成の拒否を検証します。一時フォルダーは終了時に削除し、既存プロジェクトは変更しません。Node.jsやExcelは起動しません。VS Codeの入力画面、Gitビューの自動検出、Excel上のVBAコンパイル・実行はこのテストの対象外です。
